## Follow-up: personal restoration, device retention and passkeys

- Customise my home is visible under the welcome name and shows the active player. It saves home shortcuts, game visibility, favourites and background/appearance. Per-game Play / settings retains difficulty, level count, timing and session length separately for My Games and All Games.
- Account sign-in restores the same stable profile ID and its display/language/sound/scenery/dashboard/game settings. Multi-player accounts open the player chooser. The last selected account player is remembered on that device. Rename does not change identity. Personal media files remain device-local.
- Removed the 300-entry local history limits. Independent account player copies remain in device storage after sign-out and remote replacement; restore them through the player menu. Copies merge historical entries only within the same account/profile ID, never by name. They do not enter account exports.
- Destructive controls appear only for the selected player. Exact-name confirmation is required, with account-password verification for connected profiles. History clearing preserves unlocked progress/stars and garden growth; removing a player deletes that active profile. Other players and independent copies remain.
- This is not per-person authorization on shared local profiles or within a group account. Device/browser data clearing can erase records; capacity/eviction limits remain. The privacy text explicitly states that account copies remain accessible in the browser after sign-out.
- Real WebAuthn uses pinned SimpleWebAuthn dependencies, required user verification, password reauthentication for enrollment/removal, one-use expiring session/cookie-bound challenges, origin/RP validation and signature checking. Recovery password reset revokes existing passkeys. See README-PASSKEYS.md and the additive migration.
- Backend tests use generated P-256 credentials and signed assertions. Frontend tests cover capability gating, cancellation, failed verification, successful profile loading, setup and Escape. The portable preview labels device authentication as simulated and never calls the native passkey API.
