Mind Garden v5.0.1 — audit and correction register

15 November 2026 · Pebblebrooks/mindgarden · v5-development · remote commit a4a186b22297d6ebe8e15231dd49affda300db32

Read-only app audit. No app code, branch, database or deployment changes made.
The latest menu positioning is approved. This register separates confirmed issues and approved design gaps from unresolved test failures and verification limits. It is not a certification that every possible error has been found.

Audit scope and result

Reviewed the current release sources, the supplied UI screenshots, menu/account/About/scenery behaviour through targeted bilingual DOM probes, the full set of 109 test entry points matching the regression-test naming pattern, syntax checks and literal release asset references. Five other files in tests were helpers or non-matching scripts and were not counted as test runs. No new rendered visual sweep was completed; see limits below.

67 test runs passed; 39 failed; 3 timed out. These are run outcomes, not 42 confirmed app defects. A failed test does not verify the remainder of that flow. The passing checks include current v5 flow, approved game controls, result dialogs, account API/sync/flow, passkey server logic, storage-failure handling, player preferences, matching-pair fast taps, room8/lifecycle, scenery theme pairing, media lifecycle and several game families. Syntax checks passed. No missing literal index assets or service-worker precache files were found.

Unresolved risks and verification gaps

PriorityFinding and required follow-up
HighVerification gap: multiplayer UI

Several host/join/bingo/rejoin tests fail before completing their flows; lower-level room8, room lifecycle and online expansion API checks pass. This does not establish either a live outage or a clean multiplayer release. Repair/diagnose the harness, then run two independent sessions and an eight-player capacity test against an isolated backend.

HighVerification gap: regression suite

109 test entry points were attempted: 67 pass, 39 nonzero exits, 3 timeouts at 90 seconds. Known stale expectations include hidden home cards, old nav controls, dailyGo, 8 scenery choices instead of 18, old Connect the Dots controls and old tooltip behaviour. Several jsdom suites lack showModal support. Reconcile tests with v5 before using them as release gates.

MediumVerification gap: browser and physical-device coverage

Rendered browser suites could not launch in this environment: bundled Chromium was missing, and the installed Chromium failed because its socket operation was not permitted. No new real-browser visual sweep was completed in this audit. Validate 320/390px phones, portrait/landscape tablets, desktop, EN/ZH, light/dark and 100/150/200% text after corrections.

MediumVerification gap: full game/level matrix

The all-level suite printed completed 120-session/728-round passes but continued running and hit the time limit; depth progression reached 300 launch checks before timing out; personal-games also timed out. Treat these as partial coverage, not clean completed runs. Ensure harness teardown terminates and rerun to completion.

MediumOffline installation/update fragility

All 372 precache entries exist, totalling about 29.11 MB locally. Installation fetches every entry sequentially and fails if any asset fails; network-first responses update individual cached assets. This is a source-level resilience risk, not an observed user outage. Review essential-shell vs optional-media caching and test interrupted deployments/offline upgrades.

MediumMaintainability and rule conflicts

The release bundles 60 script sources and many versioned CSS layers. Competing overrides and repeated DOM transformations contributed directly to info, caption and Animation faults. Consolidate the affected components with behaviour tests; do not indiscriminately delete older files still included in the build.

MediumRemaining production-only checks

No production sign-in, real passkey ceremony, Cloudflare D1/bindings, recovery operation, speech/audio output, physical touch gestures or 18-scene contrast measurements were performed. Do not infer these work from source inspection or mocked tests.

Recommended correction order

  1. Fix duplicate Animation transformation and restore accessible help controls.
  2. Apply approved account/player/menu/scenery/About/footer design changes as one cohesive UI revision, preserving passkeys and deletion safeguards.
  3. Repair obsolete test assumptions, dialog mocks and unfinished test teardown; investigate remaining multiplayer and preference failures.
  4. Run the responsive visual matrix and isolated account/multiplayer checks. Check long labels, focus, touch targets and natural wrapping.
  5. Only after approval and passing checks, package and push to v5-development. Verify the deployed version separately.
