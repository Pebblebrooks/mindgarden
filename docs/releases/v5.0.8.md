# Mind Garden 5.0.8

## Player changes
- My Games uses Category and Game dropdowns, Add, compact selected rows, Remove/Undo and paged selection. Removing a selection never deletes scores.
- Play Together has Rooms, In lobby and My rooms. Directory visibility does not depend on invitation delivery. Hosts and guests can retain memberships in several rooms. Each room remains capped at eight. Joined rooms resume through Open; new members cannot enter after launch.
- Local progress checkpoints are scoped by device session and room. Switching does not stop server round clocks. Results and departures are scoped to the chosen room.
- My Progress offers same-game/same-level period filters, a recent score line, by-game bars and full paginated history. Leaderboard ranks best recorded percentage scores within a game and difficulty; ties share a rank. No invented rank-change metric. Older scores without a recorded level stay separate. Online room records use room/round selectors and paginated players. Historical records are not pruned.
- Score charts are descriptive, not dementia screening or diagnosis. A separate optional performance-monitoring concept was discussed but is not implemented. Clinical screening would require clinician review and validation, consent and appropriate privacy controls.
- Gold addition, orange subtraction, rose multiplication and sage division symbols retain their mathematical shapes. Light/dark palettes differ for contrast. Home/menu icons use matching colours.
- New paired day/dusk plateau, autumn alpine lake, secular moon-gate terrace and plain stone-bridge scenery. The ten ornate cloud-palace scenes are retired from the catalogue and release assets, with saved selections migrated to Moon Gate Terrace. Five established landscapes remain; nine locations total. New images are generated and encoded as WebP, with restrained colour and no requested figurative/religious ornament.
- About latest improvements, scenery FAQ and Quick guide updated in English and Chinese.

## Data upgrade
`ensureRoomMemberships` performs an idempotent D1 batch on authenticated room API use. It adds composite (token, code) memberships and idempotent room-create requests, copies existing active memberships, installs the capacity/close triggers and removes the old one-open-room-per-host index. Scores, sessions and completed-room history remain intact. The old pointer table remains for legacy compatibility. New requests carry client-generated IDs so retrying creation does not duplicate a room.

Back up D1 before an operator-initiated rollback. Do not blindly reapply the old migration: its unique host index is incompatible with multiple active hosted rooms. A rollback requires draining/closing multiple memberships through supported room actions or a forward-compatible server patch; returning only old frontend files is not a complete database rollback.
